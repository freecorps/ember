# Ember — agent instructions

Read `docs/PLAN.md` first. It is the source of truth for design decisions (D1–D12, sections 1–21).

## Layout
- `packages/values` — `v.*` validators, Shape, JSON Schema, order-preserving index key encoding.
- `packages/server` — `defineSchema`/`defineTable`/`defineShard`, index-kind plugin API, function builders, query builder → SQL compiler, read-set recording, schema→DDL and migration planner, replica tables + their applier (`replica.ts`). Pure TS, no Cloudflare APIs.
- `packages/runtime` — Worker + Durable Objects (`Shard`, `Auth`, `System`): transactions, group commit, subscriptions, protocol, scheduler, files, cross-shard replication (`replication.ts`; Better Auth orgs in `auth-replicas.ts`).
- `packages/client`, `packages/react`, `packages/react-query` — client SDKs.
- `packages/offline` — optional offline-first `StorageAdapter`s for the client (memory, IndexedDB, SQLite/expo-sqlite, SQLite-Wasm on OPFS in a Worker, TinyBase) over `@freecorps/ember-server`'s local query execution (`runLocalQuery`), reactive local results, multi-tab coordination (`coordinateTabs`). Workerd E2E in `test/workerd`; real-Chromium E2E in `test/browser` (playwright-core, reuses an installed Playwright browser, skipped without one; with `EMBER_REQUIRE_BROWSER=1`, as in CI, a missing browser fails).
- `packages/react-native` — Expo/RN: AppState+NetInfo connectivity, AsyncStorage pending storage, SecureStore bearer auth, `registerForPush` (Expo or native token, APNs environment, Android channels).
- `packages/push` — device registry + senders for actions: Expo Push (`sendPush`, receipts) and direct APNs (HTTP/2, `.p8` ES256) + FCM v1 (`sendToDevices`), HPKE end-to-end envelopes (ported from Brigade's MIT `packages/push`); `pushComponent`. Unit tests use fake APNs/FCM (`test/fakes.ts`); `test/workerd` runs the component in workerd. Brigade's relay and mobile app are AGPL: do not copy code from them.
- `packages/expo-push` — device side of encrypted pushes: `app.plugin.cjs` (Expo config plugin adding the iOS Notification Service Extension, plain CJS, no build), `ios/EmberNotificationService/*.swift` (shipped as is), device key in SecureStore, Android decrypt task, pure-JS HPKE (noble). `test/swift.test.ts` compiles the Swift on macOS (skipped without Xcode).
- `packages/expo-updates` — `@freecorps/ember-expo-updates`: self-hosted EAS Update component (Expo Updates Protocol v1 in `protocol.ts`, rollouts in `rollout.ts`, tables/routes/dashboard in `component.ts`); `GET /manifest` answers from `caches.default` (plan + signed response keyed by the channel's version and the rollout side). `ember expo` in `packages/cli/src/expo.ts`. `test/workerd` measures the edge cache (DO stubs/RPCs per request).
- `packages/dashboard-sdk` — `@freecorps/ember-dashboard-sdk`: the page side of an `embed` block (server `dashboard.ts` kind `embed`; runtime `dashboards/embed`; dashboard Worker `src/embed.ts` serves it sandboxed under a hash-only CSP, SPA bridge in `src/app/embed.tsx`): `connect()` over `postMessage`, theme as CSS vars, `embedPage()`; `EMBED_SDK_SCRIPT` (`src/script.ts`) is generated by `bun scripts/sdk-script.ts` and committed (a test fails when stale). Zero deps. Demo: the email component's Preview tab (`packages/email/src/preview.ts`). Contract: contracts.md "Embeds".
- `packages/testing` — `@freecorps/ember-testing`: typed Node harness over the real engine (`emberTest`, `expectError`).
- `packages/eslint-plugin` — `@freecorps/eslint-plugin-ember`: syntax-only rules (string refs, async query handlers, args validators, floating mutations); RuleTester + the examples as tests.
- `packages/rate-limit`, `packages/workflows`, `packages/migrations`, `packages/workpool`, `packages/flags`, `packages/webhooks` — official components (`defineComponent`, PLAN §12; contracts.md "Componentes"). `ember migrations run|status|cancel` (packages/cli/src/migrations.ts) drives the migrations component across shards; `ember migrate convex` is the unrelated codemod. `workpool` tests: a concurrent job runner over the real engine (`test/harness.ts`), `emberTest({ app })`, and `test/workerd` (real runtime, leased action jobs).
- `packages/agent` — `@freecorps/ember-agent`: AI agent component (threads, streamed deltas, tool calls, usage) + `/react` (`useThreadMessages`, `useSmoothText`); Workers AI and AI SDK models (structural, no `ai` dependency). Node tests on the real engine with scripted models; `test/workerd` streams over a real WebSocket (contracts.md "Agent").
- `packages/sentry` — `@freecorps/ember-sentry`: error tracking compatible with the Sentry Envelope API (`POST <mount>/api/:project/envelope/`, official SDKs as is). Ingest (`ingest.ts`, envelope parser `envelope.ts`) writes no DO row: events to the component's Queue; the consumer (`consumer.ts`) symbolicates in pure JS (`sourcemap.ts` VLQ + binary search, `symbolicate.ts` LRU), fingerprints (`event.ts`) and writes one row per issue per batch (`lib:apply`); payloads gzipped to R2 by day (cron retention), time series to Analytics Engine (`analytics.ts`), alerts (`alerts.ts`); `/client` mini SDK; `ember sentry sourcemaps upload` (packages/cli/src/sentry.ts); runtime hook `defineApp({ onError })` (runtime `on-error.ts`). Node tests over `emberTest` with fake R2/Queue/AE (`test/fakes.ts`); `test/workerd` measures 0 rows at ingest (contracts.md "Sentry").
- `packages/presence` — `@freecorps/ember-presence`: presence (online per room), typing and cursors over the Shard's ephemeral channels (feature `ephemeral`: `defineApp({ channels })` in server `channels.ts`, runtime `ephemeral.ts`, client `channels.ts`; no row, no version) + `/react` (`usePresence`, `useTyping`, `useCursors`). Node tests over `FakeEmberServer({ ephemeral })`, `test/workerd` E2E (contracts.md "Feature `ephemeral`").
- `packages/flags` — `@freecorps/ember-flags`: feature flags and remote config in a component `.replicated()` table (written in `global:main`, evaluated locally in every shard, 0 RTT); pure evaluator at `/eval` (no imports: client/offline), `/react` (`FlagsProvider`, `useFlag`). Node tests on the real engine across shards; `test/workerd` shows a shard evaluating its own copy (contracts.md "Flags"). A component table can be `.replicated()` because the replica applier runs in `ComponentScopes.applier`.
- `packages/webhooks` — `@freecorps/ember-webhooks`: outbound webhooks (Standard Webhooks HMAC, rotation, retries with backoff/jitter and `Retry-After`, breaker per endpoint, DLQ, replay) over a nested `workpool`; receiver helper at `/verify` (WebCrypto only). Node tests with a fake `fetch`; `test/workerd` POSTs to fake receivers through `outboundService` (contracts.md "Webhooks").
- `packages/analytics` — `@freecorps/ember-analytics`: product analytics on Workers Analytics Engine (one data point per event, zero DO writes): `POST <mount>/track` ingest (caps, identity as the user, optional edge rate limit), optional gzip NDJSON archive in R2, counts/funnel/retention through the SQL API (`src/sql.ts`: checked names, no raw interpolation; Cache API) + `/client` (batching, `sendBeacon`, `text/plain`). Component binding `analytics_engine` (server `ComponentBinding`, CLI deploy and `ember dev`). Node tests over `emberTest` + fake SQL API; `test/workerd` counts DO rows before/after (contracts.md "Analytics").
- `packages/audit` — `@freecorps/ember-audit`: transactional audit log (`auditTriggers` for `defineTriggers`: changed fields only, redaction, size cap; `audit.log`), filtered paginated `list`, daily component cron archiving old rows to R2 as gzip NDJSON in idempotent batches (claim → write → delete). Node tests with crash/retry over `emberTest`; `test/workerd` runs the cron through `System` with real R2 (contracts.md "Audit").
- `examples/*` — small apps used as documentation and E2E drivers, one workspace each: `chat`, `todo` (offline), `files-auth-jobs`, `email-lite`. Each has `ember/` (functions + schema), a Vite/React client in `web/` (except `email-lite`), and workerd tests; `bun run check` runs them (`ember codegen` first, since `ember/_generated` is not committed). `examples/_testing` is the shared test client.
- `apps/example-expo` — Expo example (own `tsconfig.json`, not in root `tsc -b`; check with `bun run typecheck` there).
- `packages/cli` — `ember` CLI (init/dev/codegen/deploy/env/logs/projects/domains/metrics/dashboard, `migrate convex` in `src/migrate/`).
- `apps/dashboard` — Ember Dashboard: Worker API + React SPA, bundled and deployed by `ember dashboard deploy` (locally: `ember dev --dashboard`, `packages/cli/src/dev-dashboard.ts`) (own `tsconfig.json`, tests with `bun run test` there: Worker tests, real-Chromium tests in `test/browser`, skipped without a Playwright browser unless `EMBER_REQUIRE_BROWSER=1`). Contract (roles, writes, audit, endpoints) in contracts.md "Dashboard"; `ROUTES` in `src/worker.ts` is that table in code. New runtime admin endpoints go in `packages/runtime/src/admin-api.ts` and `ADMIN_FEATURES`. E2E against a real runtime: `examples/files-auth-jobs/test/dashboard.test.ts`.
- `docs/spikes/*` — evidence from prototypes. Reuse ideas, do not import from there.

## Conventions
- Bun workspaces; TypeScript strict; tests with Vitest. Runtime tests use `@cloudflare/vitest-plugin` (workerd).
- Package `exports` point to `dist/` (what npm gets) plus a `"@freecorps/ember-source": "./src/*.ts"` condition that tsconfig, Vitest (`vitest.shared.mjs`), Metro and the CLI enable in the repo: tests, typecheck and `ember dev` run from source, no build needed. A new entry point needs both (see `docs/RELEASING.md`). `bun run build` / `bun run verify:pack` before touching packaging.
- `packages/values` and `packages/server` must not import Cloudflare or Node-only APIs (they run in workerd, browsers and RN). Tests may use `node:sqlite` as a stand-in for DO SQLite through the `SqlDriver` interface.
- Mutations are synchronous inside; I/O only in actions (PLAN D6).
- Keep commits small, conventional-commit style. Run `bun run check` before committing (it includes `lint:any`: explicit `any` in `packages/*/src` may only go down; `bun scripts/check-any.ts --update` after removing some).
- Public API typing follows `docs/design/dx.md`: references only (`unsafeRef` as the explicit way out), `unknown` over `any`, application errors through `defineErrors`.
- The dev laptop is modest: avoid running more than one heavy test suite or build at a time.
- CI (`.github/workflows/ci.yml`) runs what `bun run check` runs as parallel jobs: the heavy suites (runtime, cli, auth, the two with `test/browser`) have their own rows in the `test` matrix, and every other workspace runs in the `rest` row, which picks up a new package by itself. A suite that grows past a couple of minutes gets its own row (and is excluded from `rest`).
